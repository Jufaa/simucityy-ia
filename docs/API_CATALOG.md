# Opciones de APIs, datos y visualización

**Elegir una base pequeña, no todos los servicios de esta página.** Comenzar evaluando MapLibre y OpenFreeMap como candidatos para visualización, una extracción acotada de Overpass para geometría y una fuente de terreno adecuada para la zona elegida. El clima, la búsqueda de lugares, el 3D avanzado, las capas de referencia y la IA son decisiones separadas.

Fecha de investigación: **2026-10-27**. Los enlaces corresponden a fuentes oficiales. Disponibilidad, condiciones, límites y acceso de la cuenta deben revisarse antes de adoptar un servicio. Este catálogo no crea cuentas ni integra proveedores. Consultar la [lista de tareas del equipo](TEAM_CHECKLIST.md) para responsables, requisitos previos y criterios de aceptación.

## Estado actual del repositorio

- **Base mínima:** frontend vacío, API Fastify con `/health`, proxy de salud de Next y contrato compartido de salud.
- **Sin dependencias ni configuración de producto:** se retiraron MapLibre, Three.js, la configuración de OpenFreeMap y los módulos anticipados de geografía, simulación, IA y base de datos.
- **Por evaluar e implementar:** todos los proveedores y módulos de dominio de esta página. Las ubicaciones sugeridas son futuras, no integraciones existentes. Consultar el [comportamiento actual de la API](../README.md#current-api-reference).

## 3D y simulación — responsabilidades separadas

| Componente                                                                                                                                       | Qué hace                                                                                                         | Qué no hace                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| [Extrusión de edificios en MapLibre](https://maplibre.org/maplibre-gl-js/docs/examples/display-buildings-in-3d/)                                 | Dibuja contornos con altura cuando la fuente la proporciona.                                                     | No crea alturas faltantes oficiales, fachadas fotorrealistas ni modelos de daño estructural.                         |
| [Terreno 3D de MapLibre](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/)                                                          | Representa terreno/teselas de elevación.                                                                         | No valida el terreno de origen ni su adecuación/resolución para calcular inundaciones.                               |
| [Capas/modelos personalizados con Three.js](https://maplibre.org/maplibre-gl-js/docs/examples/add-3d-tiles-3d-objects-and-models-using-threejs/) | Modelos opcionales, integración de 3D Tiles y efectos personalizados dentro del mapa.                            | No proporciona datos urbanos ni motor de inundación/evacuación. Agrega complejidad de GPU, recursos y ciclo de vida. |
| Futuro `packages/simulation-core`                                                                                                                | Motor de dominio compartido por construir; aquí podría implementarse la inundación y el cálculo de rutas reales. | No depende de un renderizador ni proveedor de IA particular para calcular resultados.                                |

Empezar con capas simples de agua/calles y marcadores de agentes. Las mallas fotográficas, teselas de terreno visual y DEMs de simulación son archivos diferentes. Agregar una plataforma de ciudad fotorrealista solo para edificios extruidos simples es alcance innecesario hasta identificar una necesidad real.

## Lista de verificación para adoptar un proveedor

Copiar para **cada proveedor elegido**; un servicio opcional evaluado/pospuesto no es una obligación principal pendiente.

- [ ] **Responsable y necesidad:** nombrar a la persona, función y razón por la que no alcanza un conjunto local de prueba o una entrada manual.
- [ ] **Evidencia:** registrar URL oficial, fecha de revisión, respuesta de muestra y dudas de acceso pendientes. Reintentar verificaciones antes fallidas.
- [ ] **Cobertura y significado:** verificar área/país reales, resolución, terreno frente a superficie, valores faltantes, unidades, sistema de coordenadas, datum vertical y fechas.
- [ ] **Derechos:** registrar licencia, texto/ubicación de atribución, permisos de redistribución/caché y restricciones comerciales/no comerciales.
- [ ] **Cuenta y gastos:** acordar titular de credenciales, uso/despliegue permitido, cuotas, presupuesto acumulado y comportamiento al agotarlo. Nunca poner claves en variables públicas, datos de prueba ni código del navegador.
- [ ] **Adaptador tipado:** reutilizar esquemas compartidos, validar datos externos, normalizar unidades y guardar procedencia observada/derivada/sintética con fuente, fecha de descarga y versión.
- [ ] **Límites operativos:** definir tiempo límite, cancelación, tasa, tamaño/área máximos, política de reintentos, descargas controladas y política de caché/actualización/versionado.
- [ ] **Fallos y reproducibilidad:** crear datos de prueba representativos guardados y casos de indisponibilidad/error; archivar entradas exactas de clima/importación para no volver a consultar datos en vivo que cambian al reproducir.
- [ ] **Aceptación:** las pruebas de contrato demuestran respuestas válidas/inválidas y estados de fallo visibles. Registrar elegido/pospuesto/rechazado y revisor antes de conectar la integración real.

Ningún servicio evita implementar y probar propagación de inundaciones, búsqueda de caminos, capacidad de refugios o comparación justa de ejecuciones. La IA consume esas capacidades, no las reemplaza.
